## Decision summary

| Layer | Runtime | Responsibility |
|-------|---------|----------------|
| **Payment rail** | TypeScript (`@agent-rails/mcp`, `@agent-rails/sdk`) | `execute_payment*` only; audited; never generated by LLM |
| **Static integrations** | TypeScript (`@agent-rails/integrations`) | Jupiter, catalog — ship with templates |
| **Dynamic connectors** | Python (`services/connector-host`) | FastMCP stdio; declarative OpenAPI / tool YAML / MD frontmatter |
| **Orchestrator chat** | TypeScript dashboard (`system-prompts.ts`) | Plans, drafts, emits connector specs — **no** `tools` on chat route today |
| **Agent execution** | Cursor / Claude Code + MCP bundle | Spawns TS payment MCP + Python connector host per workflow |

**Non-negotiable:** LLM output for connectors is **declarative JSON/YAML only** (Approach B). No sandboxed execution of `@mcp.tool()` code from the model.

## Import formats

| Format | Extensions | MCP mapping |
|--------|------------|-------------|
| OpenAPI 3 | `.json`, `.yaml`, `.yml` | One tool per operationId; HTTP caller |
| Declarative tool bundle | `.yaml`, `.json` | `tools[]` with `url`, `method`, `parameters` |
| Markdown skill + tools | `.md`, `.mdx` | YAML frontmatter `tools:` + body = agent instructions |
| Postman Collection v2.1 | `.json` | Convert requests → declarative tools (phase 2) |
| GraphQL | `.graphql`, `.gql` | Named queries → tools (phase 2) |

## Architecture

```
User chat (Chief of Staff, read-only tools)
       │
       ├─► Emits ConnectorBundle JSON (session-scoped, unprivileged)
       │
       ▼
Dashboard store (mcps[] row: command=python, args=[-m, agent_rails_connector, --bundle, …])
       │
       ▼
Agent runner (executor / analyst)
       ├── agent-rails-mcp (TS, static)     → execute_payment*
       ├── agent-rails-integrations (TS)    → jupiter_quote, …
       └── agent-rails-connector (Py)       → dynamic HTTP tools only
```

Every dynamic HTTP response should include a stable `vendor_reference_id` field when the agent later calls `execute_payment` (memo / metadata), so off-chain intent bundles stay auditable.

## Bundle v1

```yaml
apiVersion: agent-rails.connector/v1   # optional, the only accepted value
name: sample-weather                   # ^[a-z][a-z0-9-]{0,63}$ — becomes the MCP row name
description: Read-only weather quotes for workflow planning.
baseUrl: https://api.example.com       # optional; tools may then use relative urls
env:                                   # names the bundle reads; "" = runner must supply it
  WEATHER_API_KEY: ""                  # never AGENT_RAILS_*, SOLANA_*, CONNECTOR_*
instructions: ""                       # markdown import body; served as MCP instructions
tools:                                 # 1..32
  - name: weather_now                  # ^[a-z][a-z0-9_]{0,63}$, no governance/key token
    description: Current conditions (read-only).
    method: GET                        # GET|POST|PUT|PATCH|DELETE
    url: /v1/weather/{city}            # {param} filled from arguments, URL-encoded
    query: { lang: en }                # static; {{ENV:NAME}} allowed anywhere in a value
    headers:
      Authorization: "Bearer {{ENV:WEATHER_API_KEY}}"
    body: null                         # static JSON body, merged under arguments
    argumentsIn: null                  # query|body; default query for GET/DELETE, else body
    parameters:                        # JSON-schema subset; names become Python kwargs
      type: object
      properties:
        city: { type: string }
        units: { type: string, enum: [metric, imperial] }
      required: [city]
```

Unknown keys are rejected on both sides. Each call returns
`{connector_tool, vendor_reference_id, http_status, data | error, truncated?}`.

Host env: `CONNECTOR_HTTP_TIMEOUT_MS` (15000), `CONNECTOR_ALLOWED_HOST_SUFFIXES`,
`CONNECTOR_ALLOW_HTTP=1` and `CONNECTOR_ALLOW_PRIVATE_HOSTS=1` (local testing only).
